# 基于 HOG 特征和线性 SVM 的行人检测实验步骤

## 一、实验目的与总体思路

本实验采用 HOG（方向梯度直方图）描述人体的局部边缘结构，使用自行训练的线性 SVM 区分行人与背景，并通过多尺度滑窗在完整场景中定位行人。本实验不使用 OpenCV 自带的预训练行人分类器。

训练阶段的输入是带有类别标签的固定大小窗口：正样本包含完整行人，负样本为背景。SVM 学习判断窗口是否符合行人外观，并不直接预测整张图片中的人体坐标。检测阶段通过滑窗生成不同位置、不同大小的候选区域，再逐个分类、筛选和去重，得到最终检测框。

整体流程为：

```text
训练：原始场景及标注 → 样本裁剪与增强 → HOG 特征 → 初步训练 SVM
     → 难负样本挖掘 → 再次训练 → 验证与模型保存

检测：完整图片 → 多尺度滑窗 → HOG 特征 → SVM 得分
     → 阈值筛选 → IoU NMS → 包含关系去重 → 输出行人框
```

## 四、生成训练样本

### 1. 根据标注生成正样本

读取每个标注文件中的人体边界框，在对应的完整训练图片中裁剪人体区域。裁剪窗口以人体为中心，尽量覆盖完整人体并保留少量上下文，调整为宽高比约为 1:2 的区域，再缩放为 `64×128`。

每个人体标注默认生成原始裁剪、两组轻微平移和尺度扰动，以及各自的水平翻转，共六个正样本，标签设为 `1`。

这样做是为了统一人体在窗口中的相对位置和尺寸，使模型能够学习较稳定的人体结构，而不是把整张图片的背景当作行人特征。

### 2. 生成普通负样本

从 `Train/neg` 中每张背景图默认随机裁剪四个 `64×128` 窗口，标签设为 `0`。尺寸不足的背景图先缩放到目标大小。

### 3. 按来源场景划分训练集与验证集

使用 `GroupShuffleSplit`，以原始图片为分组单位划分训练与验证数据，验证分组比例设为 `0.2`，随机种子设为 `42`。同一原图产生的裁剪及增强样本必须位于同一个集合，避免相似样本同时进入训练和验证，导致指标偏高。

## 五、提取 HOG 特征

将每个样本转为灰度图，并使用相同的 HOG 配置提取特征：

| 参数 | 配置 |
|---|---|
| 窗口大小 | `64×128` |
| Block 大小 | `16×16` |
| Block 步长 | `8×8` |
| Cell 大小 | `8×8` |
| 梯度方向分箱数 | `9` |
| 每个窗口的特征维数 | `3780` |

HOG 统计局部区域中的梯度方向分布，并进行块归一化，用一组数字描述人体轮廓及边缘结构。训练和检测必须使用相同的 HOG 配置。

## 六、训练线性 SVM 并挖掘难负样本

将训练样本的 HOG 特征及标签输入 `LinearSVC`，使用 `C=0.01`、`class_weight="balanced"` 和 `max_iter=10000` 训练初步模型。

线性 SVM 学习权重和偏置，窗口得分可以表示为：

```text
score = w · HOG(window) + b
```

得分越高，表示模型越倾向于将该窗口判断为行人。该值不是概率，可以大于 1，也可以为负数。

为减少背景误检，使用初步模型进行一轮难负样本挖掘：

1. 扫描训练分组中的背景场景，收集被模型打出较高分数的背景窗口。
2. 扫描训练分组中的正场景，只收集与所有已标注人体的 IoU 都小于 `0.10` 的高分窗口，尽量避免将人体区域当作背景。
3. 两类场景分别最多扫描 200 张，每张最多收集五个难负样本，得分筛选下限为 `0.3`。
4. 将挖掘出的窗口标记为负样本，与原训练样本合并，再次拟合 SVM。

挖掘过程不使用验证集或测试集。正场景中仍可能存在未标注行人，因此低标注重叠只能降低误标风险，不能完全保证窗口里没有人。

在项目目录执行训练：

```powershell
python .\train.py
```

程序自动完成样本准备、特征提取、训练、挖掘和验证，输出：

```text

models/hog_svm.metrics.json  样本统计、分类指标和检测校准记录
```

## 七、验证模型效果

验证分为窗口分类和完整场景检测两部分：

- 窗口分类：在未参与训练的裁剪样本上计算准确率、精确率、召回率和 F1，评价单个窗口的分类能力。
- 场景检测：在保留的完整验证场景中运行滑窗检测，将预测框与标注框匹配，评价定位、误检和漏检。

检测评价以 IoU 达到 `0.5` 为匹配条件，并限制每个标注框只能匹配一次。正确匹配为 TP，多余或未匹配的预测框为 FP，未被匹配的标注为 FN：

```text
Precision = TP / (TP + FP)
Recall    = TP / (TP + FN)
F1        = 2 × Precision × Recall / (Precision + Recall)
```

`train.py` 默认从验证分组中分别选取最多 15 张正场景和 15 张负场景，以 `stride=8`、`scale-step=0.8` 扫描，比较若干得分阈值和 NMS 阈值，保存 F1 最高的配置。窗口分类成绩好，并不表示整图检测同样准确。

实验曾记录约 `0.33` 的场景检测 F1，这是当时的校准结果。后续修改了检测步长、尺度间隔和包含关系去重，不能将旧数值直接当作当前最终配置的成绩；若需要最终定量成绩，应按最终配置重新评价。

## 八、在完整图片上检测行人

`detect.py` 加载自行训练的模型，建立逐级缩小的图像金字塔，在每一层用 `64×128` 窗口滑动扫描，提取 HOG 并计算 SVM 得分，再将窗口位置映射回原图。

目前程序的检测默认值为：

| 参数 | 当前值 | 作用 |
|---|---|---|
| `stride` | `4` | 每层图片上滑窗移动的像素数 |
| `scale-step` | `0.9` | 下一层相对当前层的缩放比例 |
| `threshold` | `1.0` | 保留候选框的最低 SVM 得分 |
| `nms-overlap` | 从模型读取，当前模型为 `0.35` | 普通 IoU 去重阈值 |

当前缩放方式为 `scale *= scale_step`，因此尺度比例应满足 `0 < scale-step < 1`。接近 1 时尺度搜索更密，同时计算量更大。检测参数只改变搜索和筛选过程，不更新 SVM 权重。

单张检测命令如下，程序会自动创建输出目录：

```powershell
python .\detect.py `
    --image .\data\test\crop001573.png `
    --output .\outputs\final\crop001573.png
```

## 九、抑制重复框与人体局部框

候选框通过得分阈值后，按两步进行处理：

1. 普通 IoU NMS：优先保留高分框，抑制与其 IoU 超过阈值的其他框。
2. 包含关系去重：在剩余框中，若小框面积小于大框的 60%，至少 90% 的小框面积被大框覆盖，且横向中心距离不超过大框宽度的 20%，则删除疑似局部的小框。

第二步主要处理全身框内同时出现腿部、躯干框的问题。它执行的是删除重复候选框，不是将坐标合并。前后遮挡的不同人物也可能满足上述条件，因此需要检查是否误删真实行人。

将最终框以绿色画在原图上，并标注 `person` 和 SVM 得分。输出使用图片编码后写入文件的方式，以支持中文目录。

## 十、批量生成检测结果

将待检测图片放入 `data/test`，在项目目录执行以下 PowerShell 命令。无需再手动传入已设好的三个默认检测参数。

```powershell
$outputDir = ".\outputs\final"
New-Item -ItemType Directory -Force -Path $outputDir | Out-Null

Get-ChildItem -LiteralPath ".\data\test" -File |
    Where-Object { $_.Extension -in ".png", ".jpg", ".jpeg", ".bmp" } |
    ForEach-Object {
        Write-Host "正在检测：$($_.Name)"
        python .\detect.py `
            --image $_.FullName `
            --output (Join-Path $outputDir $_.Name)
    }
```

结果保存到 `outputs/final`。检查框是否覆盖完整人体、是否存在重复框、是否框中背景，以及是否漏掉真实行人。同名输出再次运行会被覆盖。

## 十一、实验结果分析与局限

根据本次图片观察，标注框裁剪训练、难负样本挖掘以及两步去重改善了部分场景中的定位和重复框问题，但遮挡、特殊姿态、复杂背景以及远处小行人仍可能漏检，不能认为已在所有场景中准确识别。

对 `crop001661.png` 的诊断中，在 `stride=4`、`scale-step=0.9`、`threshold=1.0` 下检查了 248840 个候选窗口。中央两个标注行人对应的 IoU 不低于 0.5 的窗口中，最高得分分别约为 `0.293` 和 `0.447`，均未通过阈值；其中一个窗口与真实框的 IoU 达到约 `0.853`。因此，这张图的中央行人漏检主要发生在得分筛选阶段，并非包含关系去重所致。

该结果说明扫描参数不能完全弥补模型对某些人体外观的识别不足。另一方面，当前检测器主要通过缩小图片搜索较大的目标，对原图中明显小于 `64×128` 的行人缺乏合适窗口，也会产生漏检。

本实验展示了传统 HOG 加线性 SVM 的完整检测流程及其局限。训练和自动校准没有使用 Test 数据，但后续曾依据测试图片的视觉结果调整检测参数和后处理，因此这些图片也承担了开发检查用途，不能再将其表现视为完全独立的最终泛化评价。严格评价需要另外保留未用于调参的数据。

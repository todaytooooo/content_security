# LeNet 轻量分类头对照实验

实验日期：2026-10-22。本实验按照预先确定的方案保留 Log-Mel 特征和 LeNet 的两层卷积，仅整体替换分类头。两个版本均从零训练，原版权重与结果未覆盖。

## 改动与控制条件

- 原版 dense：Flatten → Linear(6032→120) → Tanh → Linear(120→84) → Tanh → Linear(84→10)。
- 轻量 gap：1×1 Conv(16→64) → ReLU → AdaptiveAvgPool2d(1) → Flatten → Dropout(0.3) → Linear(64→10)。

前两层卷积、Tanh、平均池化保持一致。数据划分仍为训练 7000 条、验证 816 条、测试 837 条，另有 79 条训练候选样本因与验证同源被排除。复用相同特征缓存，训练集标准化统计量完全一致。两个版本的初始卷积骨干参数也相同。

Adam、学习率 0.001、weight decay 0.0001、batch size 64、种子 42、最多 60 轮、验证损失早停耐心 12 轮全部不变。使用同一台 RTX 4060 Laptop GPU 和相同软件环境。模型结构变化和 Dropout 会改变训练随机数消耗，因此不能宣称每轮样本顺序完全相同。

对照脚本核验了划分清单字节一致、标准化统计量数值一致、主要训练设置一致、初始卷积骨干参数一致。这是“分类头整体替换”的实验，包含池化、非线性、Dropout 和参数量等多项变化，不能单独归因于某一个组件。

## 实际结果

| 指标 | 原版 dense | 轻量 gap |
| --- | ---: | ---: |
| 总参数量 | 737546 | 4310 |
| 实际训练轮数 | 16（早停） | 60（达到上限） |
| 验证损失选中的轮次 | 4 | 59 |
| 选中轮训练准确率* | 79.86% | 52.21% |
| 选中轮验证准确率 | 57.97% | 49.75% |
| 选中轮验证损失 | 1.2786 | 1.3466 |
| 测试准确率 | 46.48%（389/837） | **51.37%（430/837）** |
| 测试 macro-F1 | 49.82% | **50.38%** |
| 测试交叉熵 | 1.8282 | **1.3601** |

参数量下降约 **99.42%**；本次测试准确率增加 **4.90 个百分点**，macro-F1 增加 **0.56 个百分点**。新权重重新加载并在 CPU 上评估，accuracy 与 macro-F1 与 GPU 一致；损失仅有约 1.3×10⁻⁶ 的浮点差异。评估和单音频预测入口均已验证。全部 10 项单元测试通过，包含轻量头梯度更新、保存加载以及旧版权重兼容性。

*训练指标来自训练过程：Dropout 开启且参数随 batch 更新；验证时 Dropout 关闭。因此 gap 的训练/验证准确率差不能视为严格同条件下的泛化差距。

## 如何理解

轻量版本没有出现原版那样训练准确率快速逼近 100%、验证损失持续升高的现象，过拟合迹象明显减轻；同时训练与验证准确率都较低，表明当前模型可能受到表达能力或优化进程的限制。它在第 59 轮仍取得新的最低验证损失，60 轮结束时并未触发早停，不能断言已经充分收敛。

全局平均池化去掉空间位置相关的大型全连接层，降低记忆能力，但也丢弃了频率和时间位置。现有浅层卷积的局部特征随后被全局平均，可能不足以保留所有声音类别所需的模式。Dropout 也可能使这个仅 4310 参数的模型更难拟合。以上是解释假设，尚未通过单组件消融验证。

本次测试准确率提高，但验证准确率更低、macro-F1 提升有限，因此不能称为所有方面都改善。尤其不应因为本次 fold10 分数较高，就将它当成一个可反复调参的验证集。这是单种子、单测试 fold 的探索性对照，没有显著性或跨 fold 稳定性证据。

结论：**该分类头确实大幅压缩参数，并在当前 fold10 上提高准确率，但仍需更强的特征提取或更合理的池化方式验证其泛化能力。** 下一步若继续研究，应预先确定方案，在验证集上比较，例如仅沿时间轴池化以保留频带位置，或使用更强的轻量卷积骨干；当前未自动追加这些实验。

## 复现与产物

在本目录执行：

```powershell
$AudioPython = "D:\Tools\Anaconda\envs\content-security\python.exe"
& $AudioPython -m unittest -v test_audio_classification.py
& $AudioPython -u audio_classification.py train --head gap --output outputs/lenet5_gap_repeat
& $AudioPython audio_classification.py evaluate --checkpoint outputs/lenet5_gap_repeat/test_fold10/best.pt
```

本次结果保存在 `outputs/lenet5_gap/test_fold10/`，包含 `best.pt`、`config.json`、`history.json`、`metrics.json`、划分清单、逐条预测、训练曲线与混淆矩阵。

运行 `compare_heads.py` 可从本次两个固定实验目录重新生成 `outputs/head_comparison/comparison.json`、`comparison.csv` 和 `head_comparison.png`。如果需要比较其他路径，应先修改脚本中的实验路径。

默认 `--head dense` 仍保留原版行为；`--head gap` 默认输出 `outputs/lenet5_gap`。已存在权重时拒绝覆盖。评估/预测自动按权重中的 `config.head` 建模，历史权重没有该字段时使用 dense。

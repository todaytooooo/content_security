# LeNet 分类头与池化方式对照实验

实验日期：2026-10-22。本实验按照预先确定的方案保留 Log-Mel 特征和 LeNet 的两层卷积，仅整体替换分类头。两个版本均从零训练，原版权重与结果未覆盖。

## 改动与控制条件

- 原版 dense：Flatten → Linear(6032→120) → Tanh → Linear(120→84) → Tanh → Linear(84→10)。
- 轻量 gap：1×1 Conv(16→64) → ReLU → AdaptiveAvgPool2d(1) → Flatten → Dropout(0.3) → Linear(64→10)。
- 时间池化 time：1×1 Conv(16→64) → ReLU → AdaptiveAvgPool2d((13, 1)) → Flatten → Dropout(0.3) → Linear(832→10)。输出特征图为 64×13×1，因此仅沿时间维平均，保留 13 个频率位置。

前两层卷积、Tanh、平均池化保持一致。数据划分仍为训练 7000 条、验证 816 条、测试 837 条，另有 79 条训练候选样本因与验证同源被排除。复用相同特征缓存，训练集标准化统计量完全一致。两个版本的初始卷积骨干参数也相同。

Adam、学习率 0.001、weight decay 0.0001、batch size 64、种子 42、最多 60 轮、验证损失早停耐心 12 轮全部不变。使用同一台 RTX 4060 Laptop GPU 和相同软件环境。模型结构变化和 Dropout 会改变训练随机数消耗，因此不能宣称每轮样本顺序完全相同。

对照脚本核验了划分清单字节一致、标准化统计量数值一致、主要训练设置一致、初始卷积骨干参数一致。这是“分类头整体替换”的实验，包含池化、非线性、Dropout 和参数量等多项变化，不能单独归因于某一个组件。

## 实际结果

| 指标 | 原版 dense | 轻量 gap |
| --- | ---: | ---: |
| 总参数量 | 737546 | 4310 |
| 实际训练轮数 | 16（早停） | 60（达到上限） |
| 验证损失选中的轮次 | 4 | 59 |
| 选中轮训练准确率* | 79.86% | 52.21% |
| 选中轮验证准确率 | 57.97% | 49.75% |
| 选中轮验证损失 | 1.2786 | 1.3466 |
| 测试准确率 | 46.48%（389/837） | **51.37%（430/837）** |
| 测试 macro-F1 | 49.82% | **50.38%** |
| 测试交叉熵 | 1.8282 | **1.3601** |

2026-10-22 新增的时间池化版本保持上表中两版的所有控制条件，使用相同 split manifest、训练标准化统计量、随机种子、优化器与初始卷积骨干。11 项自动测试通过，并直接验证时间池化层会平均 29 个时间单元、但不平均 13 个频率位置。结果如下：

| 指标 | dense | 全局池化 gap | 时间池化 time |
| --- | ---: | ---: | ---: |
| 总参数量 | 737546 | 4310 | 11990 |
| 实际训练轮数 | 16 | 60 | 27（早停） |
| 验证损失选中的轮次 | 4 | 59 | 15 |
| 选中轮训练准确率* | 79.86% | 52.21% | 72.99% |
| 选中轮验证准确率 | 57.97% | 49.75% | **58.70%** |
| 选中轮验证损失 | 1.2786 | 1.3466 | **1.2567** |
| 测试准确率 | 46.48% | **51.37%** | 49.94% |
| 测试 macro-F1 | 49.82% | **50.38%** | 50.20% |
| 测试交叉熵 | 1.8282 | **1.3601** | 1.4827 |

时间池化相对 dense 的测试准确率增加 3.46 个百分点、macro-F1 增加 0.38 个百分点，但比全局池化低 1.43 个百分点 accuracy 和 0.18 个百分点 macro-F1。它的验证损失优于另两者，却未在 fold10 测试集获胜，不能以测试结果回过头重选方案；这正说明单一验证 fold 的不确定性。该版本的权重重载 CPU 评估与 GPU 指标一致，损失仅有约 6×10⁻⁷ 浮点差异；单音频预测入口也已验证。

参数量下降约 **99.42%**；本次测试准确率增加 **4.90 个百分点**，macro-F1 增加 **0.56 个百分点**。新权重重新加载并在 CPU 上评估，accuracy 与 macro-F1 与 GPU 一致；损失仅有约 1.3×10⁻⁶ 的浮点差异。评估和单音频预测入口均已验证。全部 10 项单元测试通过，包含轻量头梯度更新、保存加载以及旧版权重兼容性。

*训练指标来自训练过程：Dropout 开启且参数随 batch 更新；验证时 Dropout 关闭。因此 gap 的训练/验证准确率差不能视为严格同条件下的泛化差距。

## 如何理解

全局池化版本没有出现原版那样训练准确率快速逼近 100%、验证损失持续升高的现象，过拟合迹象明显减轻；同时训练与验证准确率都较低，表明当前模型可能受到表达能力或优化进程的限制。它在第 59 轮仍取得新的最低验证损失，60 轮结束时并未触发早停，不能断言已经充分收敛。

全局平均池化去掉空间位置相关的大型全连接层，降低记忆能力，但也丢弃了频率和时间位置。时间池化保留频率位置后，训练能力与验证损失均改善，说明该信息有用；但 fold10 指标仍略低于全局池化，不能证明保留频率位置对所有测试场景都更好。Dropout 也可能使这些轻量模型更难拟合。以上是解释假设，尚未通过单组件消融验证。

本次测试准确率提高，但验证准确率更低、macro-F1 提升有限，因此不能称为所有方面都改善。尤其不应因为本次 fold10 分数较高，就将它当成一个可反复调参的验证集。这是单种子、单测试 fold 的探索性对照，没有显著性或跨 fold 稳定性证据。

结论：**三种分类头中，全局池化 gap 在当前 fold10 上准确率和 macro-F1 最高；时间池化 time 的验证损失最佳且也优于原版，但未超过 gap 的测试成绩。** 后续应在预先确定的方案下做多 fold/多种子验证，或先在验证集上比较仅调整 Dropout/训练轮数等单组件，不能继续根据 fold10 分数调参。

## 复现与产物

在本目录执行：

```powershell
$AudioPython = "D:\Tools\Anaconda\envs\content-security\python.exe"
& $AudioPython -m unittest -v test_audio_classification.py
& $AudioPython -u audio_classification.py train --head gap --output outputs/lenet5_gap_repeat
& $AudioPython -u audio_classification.py train --head time --output outputs/lenet5_time_repeat
& $AudioPython audio_classification.py evaluate --checkpoint outputs/lenet5_gap_repeat/test_fold10/best.pt
```

本次结果保存在 `outputs/lenet5_gap/test_fold10/` 和 `outputs/lenet5_time/test_fold10/`，包含 `best.pt`、`config.json`、`history.json`、`metrics.json`、划分清单、逐条预测、训练曲线与混淆矩阵。

运行 `compare_heads.py` 可从本次两个固定实验目录重新生成 `outputs/head_comparison/comparison.json`、`comparison.csv` 和 `head_comparison.png`。如果需要比较其他路径，应先修改脚本中的实验路径。

默认 `--head dense` 仍保留原版行为；`--head gap`、`--head time` 默认分别输出 `outputs/lenet5_gap`、`outputs/lenet5_time`。已存在权重时拒绝覆盖。评估/预测自动按权重中的 `config.head` 建模，历史权重没有该字段时使用 dense。
